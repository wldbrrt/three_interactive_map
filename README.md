# Интерактивная карта торгового центра

Одностраничное приложение на JavaScript с использованием ES-модулей и Three.js. Сцена формируется на основе 100 магазинов, данные которых генерируются по заданному seed, поэтому при повторном запуске расположение и характеристики объектов остаются одинаковыми.

## Запуск проекта

Для работы потребуется Node.js версии 18.x, 20.x или 22+.

npm install
npm run dev

После запуска откройте адрес, который укажет Vite. Обычно это `http://localhost:5173/`.

Чтобы запустить тесты и собрать production-версию, выполните:

npm test
npm run build

## Что реализовано

- **Генерация данных.** Функция `generatePlaces` создаёт 100 магазинов. У каждого есть ID, название, ширина, глубина и цвет. По умолчанию используется фиксированный seed, поэтому данные не меняются между запусками.

- **Расположение магазинов.** Функция `gridLayout` размещает прямоугольники на плоскости XZ, последовательно заполняя строки слева направо. Если очередной объект не помещается, начинается новая строка с учётом максимальной глубины предыдущей. Стандартный зазор между магазинами — 1, максимальная ширина строки — 40. Если магазин шире этого значения, для него выделяется отдельная строка. Пересечения проверяются с помощью `findOverlaps` и тестов.

- **Отображение сцены.** Каждый магазин представлен отдельным объектом `BoxGeometry` высотой 2. Названия выводятся с помощью `CSS2DRenderer`. Если название слишком длинное, оно сокращается многоточием. При наведении курсора или выборе магазина отображается полное название с переносом строк. Подписи всегда обращены к экрану и остаются читаемыми как в 2D-, так и в 3D-режиме.

- **Переключение режимов.** Кнопка на экране и клавиша `Space` переключают перспективный 3D-вид и ортографический 2D-план. Переход между режимами занимает около 680 мс и сопровождается плавной анимацией камеры. В 3D хорошо виден объём магазинов, а в 2D сохраняется единый масштаб без перспективных искажений.

- **Выбор магазинов.** При наведении магазин подсвечивается. После клика он выделяется контуром, а в информационной панели появляются его ID, название, координаты и размеры. Эти же ID, название и позиция выводятся в консоль.

## Структура проекта

Код разделён на несколько частей, каждая из которых отвечает за свою задачу:

- `src/data/generatePlaces.js` — генерация данных магазинов и их проверка.
- `src/layout/gridLayout.js` — размещение объектов и поиск пересечений.
- `src/scene/` — создание сцены, геометрия магазинов, подписи, камеры и управление ими.
- `src/interaction/picking.js` — обработка наведения и выбора объектов с помощью `Raycaster`.
- `src/ui/` — переключение режимов отображения и панель с информацией о выбранном магазине.
- `src/main.js` — инициализация приложения и связь между его компонентами.

## Производительность и дальнейшее развитие

В текущей версии каждый из 100 магазинов представлен отдельным `mesh`, а подписи создаются как DOM-элементы через `CSS2DRenderer`. Для такого количества объектов этого достаточно.

Если количество магазинов вырастет до 1000 и более, стоит сократить число одновременно отображаемых подписей. Например, полное название можно показывать только для выбранного или наведённого магазина, а остальные метки скрывать или упрощать в зависимости от масштаба и положения камеры. Обновлять их достаточно при изменении камеры или состояния объекта, а не на каждом кадре.

Для большого количества текстовых меток можно использовать SDF/MSDF-атласы, `CanvasTexture` или спрайты, избегая лишних перерисовок без необходимости.

Если перейти на `InstancedMesh`, при выборе объекта через `Raycaster` можно использовать `intersection.instanceId` и массив `placeIdByInstanceId`, связывающий экземпляры с ID магазинов. При объединении геометрии потребуется сопоставлять `faceIndex` с ID либо использовать отдельную упрощённую геометрию для выбора объектов. В текущей реализации с 100 отдельными `mesh` достаточно обычного `Raycaster`.

Данные магазинов хранятся отдельно от объектов Three.js. Для быстрого поиска используется `placesById: Map<id, PlaceData>`, а в `userData` каждого `mesh` записан только `placeId`. Благодаря этому информация о магазине не дублируется в графической сцене.

Если потребуется ускорить пространственный поиск, можно добавить сеточный индекс `Map<cell, Set<placeId>>`. Он позволит сначала находить магазины в нужной ячейке, а затем проверять точные границы их прямоугольников.
