# Интерактивная карта торгового центра

Небольшое SPA на JavaScript ES modules, Three.js и Vite. На карте создаются 100 магазинов с воспроизводимыми данными; доступны перспективный 3D-вид, ортографический 2D-план, навигация камерой и выбор магазина.

## Запуск

Требуется Node.js 20.19+ или 22.12+.

```powershell
npm install
npm run dev
```

Откройте URL, который напечатает Vite, обычно `http://localhost:5173/`.

Проверки и production-сборка:

```powershell
npm test
npm run build
npm run preview
```

Публичная демо-ссылка пока не настроена; публикацию выполнит владелец проекта.

## Управление

- Кнопка `План 2D` / `Перспектива 3D` переключает вид с плавным переходом.
- `Space` переключает вид, если фокус не находится на интерактивном элементе.
- В 3D перетаскивайте мышь для вращения, используйте колесо для zoom.
- В 2D перетаскивайте карту для pan, колесо меняет масштаб; вращение отключено.
- Наведение подсвечивает магазин. Клик выбирает его и открывает сведения; другой магазин заменяет выбор. Пустой клик и drag камеры выбор не снимают. Закройте панель, чтобы очистить выбор.

## Архитектура

```text
src/
	app/config.js                 Общие параметры сцены и взаимодействий
	data/generatePlaces.js        Детерминированные данные и валидация
	layout/gridLayout.js          Shelf packing и проверка пересечений
	scene/createScene.js          Сцена, свет, renderer, камеры и controls
	scene/cameraController.js     Плавное переключение 2D/3D
	scene/createPlaceMesh.js      Объёмный mesh магазина
	scene/createLabels.js         CSS2D-подписи
	scene/getCompactPlaceName.js  Короткое имя или fallback с многоточием
	interaction/picking.js        Raycaster, hover, selection и контур
	ui/createModeControl.js       Кнопка переключения режима
	ui/createPlaceDetails.js      Панель выбранного магазина
	main.js                       Связывает данные, layout, сцену и UI
```

`PlaceData` содержит только бизнес-данные: `id`, `name`, `width`, `depth`, `color`, после раскладки — `x` и `z`; при необходимости можно добавить `shortName` и ссылку на текстурный атлас/его UV-область. Three.js meshes и DOM-метки в бизнес-данные не помещаются. Сейчас `main.js` создаёт `placesById: Map<string, PlaceData>`, а mesh хранит обратную связь в `mesh.userData.placeId`.

Для роста набора рекомендуется держать индексы отдельно от бизнес-записей:

```js
const placesById = new Map();        // placeId -> PlaceData
const meshById = new Map();          // placeId -> THREE.Object3D/instance index
const placeIdByMesh = new WeakMap(); // THREE.Object3D -> placeId, если нужен обратный поиск
const spatialGrid = new Map();       // "cellX:cellZ" -> Set<placeId>
```

Поиск по ID выполняется через `placesById.get(id)` — O(1) в среднем. Для координат XZ рекомендуется spatial grid с фиксированным размером ячейки: при индексации прямоугольник магазина добавляется во все ячейки, которых касается его AABB; запрос точки получает ID из соответствующей ячейки и затем проверяет точные границы кандидатов. При перемещении магазина его ID удаляется из прежних ячеек и добавляется в новые. Для редких пространственных запросов на 100 объектов достаточно перебора; индекс полезен только после измерения необходимости.

### Размещение без пересечений

`gridLayout` обрабатывает магазины в стабильном порядке и заполняет строки слева направо. Координаты — центры прямоугольников на XZ. Перед добавлением очередного магазина проверяется ширина строки; при переполнении начинается следующая строка на глубине предыдущей строки плюс `gap`. Параметры по умолчанию: максимальная ширина строки `40`, зазор `0.5`. Магазин шире строки получает отдельную строку.

Для магазинов одной строки интервалы X разделены зазором; соседние строки разнесены по Z с учётом наибольшей глубины предыдущей строки. `findOverlaps` независимо проверяет каждую пару за O(n²), что недорого для 100 записей. Генерация размеров и цветов использует seed и даёт одинаковый результат при одинаковом seed.

### Сцена и камеры

Магазины — отдельные `BoxGeometry(width, height, depth)` с основанием на полу. Используется общая плоскость пола, hemisphere light и directional light с мягкими тенями. CSS2DRenderer показывает собственную DOM-подпись каждого магазина в постоянной точке над его центром. `labelController.js` изменяет размер и ширину метки при zoom: надписи шире при приближении и уже при удалении. Порог скрытия задаётся `labelHideDistance`; он использует расстояние перспективной камеры или эквивалентную высоту ортографического frustum. Полное название показывается только для наведённого или выбранного магазина, компактный текст остаётся для остальных. CSS2D-метки не перехватывают события мыши.

Для 3D применяется `PerspectiveCamera`, для плана — `OrthographicCamera`; у каждой свой `OrbitControls`. Переход длится 680 ms и интерполирует позицию, ориентацию и масштаб. Азимут плана наследуется от стороны текущего 3D-вида. При переходе интенсивность направленного света плавно снижается для 2D и возвращается для 3D; hemisphere light компенсирует общую яркость.

### Picking и выбор

Raycaster строит луч из указателя относительно canvas и проверяет meshes магазинов. Hover и selected используют индивидуальные материалы; selection дополнительно создаёт контур по геометрии выбранного магазина. Метки имеют `pointer-events: none`, поэтому выбор выполняется по блоку. Данные панели читаются из `placesById`, а не копируются в mesh.

Для перехода на `InstancedMesh` нужен массив `placeIdByInstanceId`, синхронный с порядком `setMatrixAt`; при hit используется `intersection.instanceId`, затем ID разрешается через `placesById`. Hover/selection можно обновлять через `setColorAt` и `instanceColor`, а контур выбранного объекта рисовать отдельным proxy-mesh.

Если геометрия объединена через `BufferGeometryUtils`, исходный mesh уже не соответствует hit напрямую. При объединении следует сохранить для каждого магазина диапазон треугольников/индексов и сопоставлять `intersection.faceIndex` с этим диапазоном. Более простой компромисс — отдельная низкополигональная pick-геометрия с таблицей диапазонов или ID. Для 100 объектов текущий Raycaster по отдельным meshes проще и достаточен.

## Масштабирование до 1000+ объектов

Текущая реализация рассчитана на 100 объектов: магазины используют отдельные `BoxGeometry` и цветные `MeshStandardMaterial`, а подписи — DOM через `CSS2DRenderer`. Ниже описан план для варианта с 1000+ магазинами, в том числе текстурированными; это не реализованная оптимизация.

- Для магазинов с общей базовой геометрией использовать `InstancedMesh`, объединяя экземпляры по совместимым geometry/material/texture atlas. Различные размеры задавать transform-матрицами, цвет — instance color. Это уменьшает draw calls, но не устраняет стоимость текстур и overdraw.
- Текстуры магазинов упаковать в один или несколько texture atlases, чтобы сократить переключения текстур и материалов. Для каждого экземпляра хранить atlas page и UV-прямоугольник; передавать UV offset/scale через instanced attribute и shader либо группировать совместимые UV-наборы в batches. Если атласов несколько, отдельный batch/material нужен на каждую страницу.
- Не создавать 1000 постоянно активных DOM-подписей. Предпочитать подписи выбранного/наведённого магазина и ограниченного числа видимых объектов; проверять frustum и projected screen-space bounds при изменении камеры, масштаба или viewport.
- Для массовых подписей использовать SDF/MSDF, texture atlas, CanvasTexture или Sprite; обновлять текстовые данные только при изменении содержимого, не каждый кадр.
- Ввести LOD текста: показывать меньше/короче подписей на дальнем масштабе и больше деталей при приближении. Пересчитывать состояния при изменении камеры/масштаба, не на каждом render frame.
- Оставить `placesById: Map<placeId, PlaceData>` и добавить `meshById`/`placeIdByInstanceId`; для поиска по координатам использовать `spatialGrid` из раздела модели данных, а при ещё больших или неравномерных наборах оценить quadtree или BVH.
- Для picking в `InstancedMesh` читать `instanceId`. Для объединённой геометрии хранить отображение диапазона `faceIndex` на `placeId` либо выполнять raycast по отдельной упрощённой pick-геометрии.
- Сначала измерить draw calls, CPU-время обновления меток, GPU frame time и память текстур; оптимизацию выбирать по обнаруженному ограничению.

Текущая сцена намеренно остаётся без InstancedMesh, texture atlas и spatial index: для 100 объектов более простая реализация легче для проверки и сопровождения.
